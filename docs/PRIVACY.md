# 隐私与脱敏规则（Privacy Rules）

> 本页规定仓库隐私保护要求。代码、文档和截图可能通过 GitHub、Git 历史及 npm 安装包传播，已传播的副本可能长期保留。
>
> 早期截图曾包含真实数据，1.19.2 已统一替换为假值。

## 0. 隐私判定

公开内容及其组合能够关联到个人、账户或设备时，须完成脱敏后再写入仓库。昵称、余额与到期时间组合也可能定位真实账户。

## 1. 绝对禁止进入仓库的内容

| 类别 | 具体形态 | 为什么 |
| --- | --- | --- |
| 凭据 | PAT（`pt-…`）、`access_token` / `refresh_token` / `security_oauth_token`、jobToken、npm `_authToken`、`ghp_…`、私钥 | 可授予账户或接口访问权限 |
| 凭据指纹 | `pat-<sha256 前 16 位>` 形式的账号 id | 可关联凭据与账号，并用于跨仓库比对 |
| 真实账号标识 | 邮箱、手机号、上游昵称（形如 `nick1234…`）、真实显示名 | 可识别个人或账号 |
| 账户财务状态 | 积分余额、套餐档位、到期时刻、账单周期 | 与账号标识合并即构成可定位画像 |
| 本机路径 | `/Users/<姓名>/…`、`C:\Users\<姓名>\…`，以及用户主目录下的其它绝对路径 | 泄露操作系统用户名与目录结构 |
| 凭据库键名 | `~/.dsh/.credentials.yaml` 里的 `QODERCN_ACCOUNT_<id>` 之类 | 指向真实凭据条目 |
| 设备标识 | UMID、machineId、machineToken、序列号、`MachineGuid` | 设备可被唯一识别 |

> 注意：**`dingminhua` 与 `@dmh2002/` 这两个是公开身份**（GitHub 仓库地址、npm
> 包作用域、MIT 版权人），它们必须留在仓库里，其他账号数据按本页规则处理。

## 2. 截图规则

截图须满足以下四项要求：

1. **使用示例数据生成截图。** 使用 `scripts/*.preview.tsx` 渲染示例，或在截图前将账号名替换为 `acct-demo`、余额替换为示例整数。
2. **遮挡必须是不透明的实心块或直接替换成假值。** **模糊 / 马赛克 / 半透明色块不符合脱敏要求**：
   模糊保留了字符宽度与字距，马赛克保留了亮暗分布，仍可用于推测字符数量和轮廓；
   本项目 0.3.0 的两张 README 截图曾使用模糊遮罩，1.19.2 已替换。
3. **账号名、余额、到期时刻同时出现时，三项均须替换为示例值。** 余额与到期时间可形成时间线比对依据。1.19.2 首次修复只替换账号名而保留原始数值，独立审查要求再次修订。示例余额和到期日使用 `888`、`01/01/2027` 等明确假值。
4. **截图前检查窗口标题、侧边栏和浏览器标签**，确认其中的其他账号标识已完成脱敏。

**新增或重拍截图后**，须检查 `docs/assets/` 中的实际图片，并核对 Markdown 的 alt 文字。

## 3. 文字规则

- 记录「用户实拍」的现象时，用 `account-a` / `account-b` / `account-c` 代替真实昵称，
  用 `account-a@example.com` 代替真实邮箱。记录问题现象并替换身份信息，例如保留“首位账号额度耗尽后仍排在最前”的现象描述。
- 代码注释同样适用。`src/` 的注释会进入 `lib/` 构建产物并随 npm 包公开分发。
- CHANGELOG 里的历史条目**不回改语义**，只做标识符替换；脱敏时须保留当时的
  技术结论。
- 日志、错误消息、`doctor` 输出已经统一走 `redactUpstreamText`（`src/probe.ts`）
  脱敏 `token=…` 一类的参数；新增日志路径时沿用同一个函数，统一使用该函数处理新增日志。

## 4. 提交前自检

```bash
# 1) 快速自查。**它不是 `tests/privacy.spec.ts` 的镜像**：下面这条只管
#    最常用的几类，自动化检查里还有私钥、令牌本体、Windows 路径等它没写的规则。
#    两项检查均须执行：先核对本项输出，再执行第 3 步。
# 占位值（pat-aaaa… / pat-deadbeef… / pat-0123456789abcdef）被排除在外，
# 否则输出会被测试数据淹没，而「看不完的输出」等于没人看。
grep -rnE 'nick[0-9]{4,}|@[A-Za-z0-9.-]+\.[a-z]{2,}|pat-[0-9a-f]{12,}|/Users/[A-Za-z0-9._-]+|/home/[A-Za-z0-9._-]+|(?<!\d)1[3-9][0-9]{9}(?!\d)|"?(machineId|machineToken|machineType)"?\s*[:=]' \
  --include='*.md' --include='*.ts' --include='*.tsx' --include='*.mjs' --include='*.json' \
  --include='*.yml' --include='*.css' --include='*.reg' . \
  | grep -v node_modules | grep -v example.com \
  | grep -viE 'pat-(0{6,}|a{6,}|b{6,}|c{6,}|d{6,}|e{6,}|f{6,}|deadbeef|cafebabe|deadc0de|feedface|0123456789abcdef|fedcba9876543210)'

# 2) 本次改动的图片，逐张打开并核对内容（自动检查仅覆盖文本）
git diff --stat -- docs/assets

# 3) 自动化检查（CI 也会跑，且是单独一步）
pnpm exec vitest run tests/privacy.spec.ts
```

> **自动化检查的适用范围：**
> - 检查依据已知坏值的黑名单。新账号名、邮箱域或昵称格式可能超出既有规则；1.19.2 的显示名泄露即属于此类情况。
> - 图片内容须由维护者人工检查。
> - 财务数值的核查只能靠人工检查。历史上曾尝试同时匹配余额和到期时间，测试数据中的 `{ credits: 100, nearestExpiryMs: … }` 产生大量误报，相关规则已撤回。修改截图时须同步替换正文引用值（见 §2 第 3 条）。
> - 检查范围包含随包发布的 `lib/`。干净 clone 须先执行 `pnpm build` 生成产物，CI 同样在 Build 之后执行隐私检查。
> - 截图须使用示例数据，并执行自动化回归检查。

## 5. 泄露处置

1. **先修当前 HEAD**：换图、替换标识符、`pnpm build`（同步更新 `lib/` 中的注释）。
2. **评估历史重写**：保留旧 commit 时，可通过 `git show <sha>:<path>` 读取旧图。
   重写历史会改掉所有 commit hash、需要 force push、使 fork 与原有提交关系需要重新同步，**不可逆**，
   必须维护者明确同意后才做；默认只修当前版本。
3. **处理已发布版本**：`npm unpublish` 只对 72 小时内、且没被依赖的版本
   生效。可行的是 `npm deprecate <pkg>@<ver> "含有已泄露的截图，请升级到 X.Y.Z"` +
   发布包含修复的新版本。
4. **在 CHANGELOG 记录泄露内容、受影响版本与修复版本。**记录替换截图的原因，供后续维护者核查。
